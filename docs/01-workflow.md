# 01. Процесс: от дизайна до сданной вёрстки

## 0. Что считается дизайном

Принимается любой формат. Как извлекать данные:

| Формат | Как работать |
|---|---|
| Ссылка на Figma | Через Figma-коннектор: `get_metadata` (структура фреймов), `get_variable_defs` (цвета, шрифты, радиусы), `get_design_context` (размеры, отступы по блокам), `get_screenshot` (сверка), `download_assets` (картинки, иконки). |
| Скриншоты / PNG / JPG | Смотреть изображения, мерить размеры по пикселям относительно ширины фрейма. Значения округлять до чётных или до шага сетки дизайна. |
| PDF | Рендерить страницы в картинки и работать как со скриншотами. |
| Ссылка на готовый сайт (Тильда, WordPress и т.п.) | Через браузер: computed-стили, скриншоты на разных ширинах. Подробно — раздел «Сайт как источник дизайна» ниже. |
| Текстовое описание / референс | Собрать прототип на базовых токенах шаблона и явно перечислить допущения. |

Если чего-то не хватает, **сначала спросить, потом верстать**. Обычно не хватает:
- мобильной версии (без неё `fluid()` не посчитать);
- состояний: hover, active, disabled, открытое меню, ошибки формы;
- исходников картинок, иконок и шрифтов.

Если ответить некому, берутся значения по умолчанию из таблицы ниже, а все допущения перечисляются в итоговом отчёте.

| Нет в дизайне | Значение по умолчанию |
|---|---|
| Мобильная версия | min ≈ 50–60% от десктопного значения для отступов, шрифты по шкале из `03-styles.md` |
| Hover | Кнопки — более светлый или тёмный тон акцента, ссылки — акцентный цвет, карточки — подсветка бордера |
| Иконки | SVG из дизайна, при отсутствии — заглушка с пометкой `TODO` |
| Шрифт | `system-ui, sans-serif` с пометкой в отчёте |

## 0.1. Сайт как источник дизайна (Тильда и другие конструкторы)

Если вместо макета прислали ссылку на живой сайт, дизайн снимается со страницы в браузере. `WebFetch` не годится: он отдаёт только текст без стилей.

### Шаг 1. Источник картинок и шрифтов

Файлы с CDN (`static.tildacdn.com` и подобных) из рабочего окружения могут не скачаться из-за ограничений сети. Поэтому до начала работы попросить один из вариантов (в порядке предпочтения):
1. **Экспорт проекта из Тильды** (Настройки сайта → Экспорт, нужен тариф Business): архив с HTML, CSS, картинками.
2. **Сохранённую страницу**: Ctrl+S → «Веб-страница полностью» в папку, к которой даётся доступ.
3. Если не сработало ни то, ни другое: попробовать скачать картинки по URL из DOM. Что не скачалось, заменить заглушками и перечислить в отчёте.

Платные шрифты (не Google Fonts и не TildaSans) нужно запросить отдельно в `.woff2`.

### Шаг 2. Снятие токенов

Открыть страницу в браузере и через JS-консоль (`getComputedStyle`) собрать:
- **Цвета.** Все уникальные `color`, `background-color`, `border-color` и цвета градиентов по всем элементам. Похожие оттенки объединить и назвать по схеме `--color-<оттенок>-<светлота HSL>`, затем назначить роли (`--color-bg`, `--color-text`, `--color-heading`, `--color-accent`, `--color-border`).
- **Шрифты.** `font-family`, набор используемых `font-weight`.
- **Типографику.** `font-size`, `line-height`, `font-weight` заголовков и основного текста. Снять на ширине 1200 и на 360, это будут max и min для `fluid-text`.
- **Радиусы, бордеры, тени.** Уникальные значения, разложить по шкалам `--border-radius-*` и `--border-width-*`.
- **Контейнер и ритм.** Ширина контента (у Тильды обычно 1200 и колонки `t-container`), вертикальные отступы блоков на 1200 и 360.
- **Ховеры.** Навести курсор на кнопки, ссылки, карточки и записать, что меняется.

### Шаг 3. Скриншоты

Сделать скриншоты каждой страницы целиком на ширинах **1200, 960, 640, 480, 360**: это брейкпоинты Тильды. Отдельно снять открытое мобильное меню, попапы и раскрытые аккордеоны.

### Шаг 4. Перенастройка `fluid()` под сетку Тильды

Ноутбучного макета у Тильды нет, контейнер у неё 1200. На старте проекта:
- `helpers/constants.scss`: `$container-desktop-width: 1200;` и `$container-laptop-width: 1200;` (laptop-интерполяция не нужна);
- `helpers/functions.scss`: `$minViewportWidth: 360;`;
- значения считать как `fluid(<на 1200>, <на 360>)`; `fluid-to-laptop` почти не используется;
- брейкпоинты шаблона (1440 / 1023 / 767 / 480) **не менять**. Резкие перестройки Тильды на 960 / 640 переносить на ближайшие миксины `tablet` / `mobile`.

### Шаг 5. Правила переноса

- **Zero Block** (элементы с абсолютным позиционированием, отдельно на каждой ширине) **не копировать координатами**. Нужно понять смысл раскладки (колонки, сетка, наложение) и собрать её на flex/grid так, чтобы на тех же ширинах выглядело так же.
- **Стандартные T-блоки** (обложки, карточки, FAQ, слайдеры) соотнести с компонентами из `_library/`: аккордеон → `Accordion`, галерея и слайдер → `Slider`, сетка карточек → `Grid`.
- **Тексты** брать дословно из DOM.
- **Формы** сверстать разметкой (`Field`, `Checkbox`, `Select`, маска телефона) с нативной валидацией. Отправка у Тильды идёт через её сервер. В отчёте отметить, что обработчик формы нужно подключать отдельно.
- **Попапы** делать на `<dialog>` (модуль по образцу `OverlayMenu`).
- **Анимации появления** (Tilda Animation) по умолчанию не переносятся. Если просят, они делаются отдельным модулем на `IntersectionObserver`.
- Классы, скрипты и инлайн-стили Тильды (`t-*`, `tn-*`) в проект **не попадают**: вёрстка пишется заново по `docs/`.

## 1. Разбор дизайна (до кода)

Сначала составить и записать план:

1. **Экраны и брейкпоинты.** Какие ширины фреймов: desktop / laptop / tablet / mobile. Эталонные ширины шаблона: desktop с контейнером 1600, laptop с контейнером 1280, mobile 390. Если у дизайна другие ширины, в начале проекта поправить `$container-desktop-width`, `$container-laptop-width` в `styles/helpers/constants.scss` и `$minViewportWidth` в `functions.scss` (см. `03-styles.md`).
2. **Токены.** Палитра (имена как в Figma, иначе по схеме `--color-<оттенок>-<светлота>`), радиусы, толщины бордеров, шрифт и шкала заголовков h1–h6, размер body, отступ секций, ширина контейнера и его padding.
3. **Декомпозиция.** Каждый экран делится на:
   - `layouts/` — то, что повторяется на всех страницах (Header, Footer, Content, Section-обёртка);
   - `sections/` — крупные блоки страницы (Hero, FAQ, Plans…);
   - `components/` — всё, что встречается ≥ 2 раз или является UI-примитивом (Button, Badge, карточки, поля).
4. **Сверка с `_library/`.** Для каждого компонента отметить: берём из библиотеки (и что перекрасить) или пишем новый.
5. **Интерактив.** Слайдеры, табы, аккордеоны, меню, селекты, маски, модалки. Для каждого выбрать модуль из библиотеки или описать новый.

## 2. Создание проекта

1. Скопировать папку `_start-template-vite` целиком в новую папку проекта, например `D:\Work\<project-name>`. Папку `_library/` в проекте можно оставить как справочник или удалить в конце.
2. В `package.json` задать `name`.
3. Заполнить `src/constants/site.js` (название, язык), `public/site.webmanifest`, заменить фавиконки в `public/`.
4. Внести токены в `styles/variables.scss` и шрифты в `styles/fonts.scss` + `src/assets/fonts`.
5. Настроить `globals.scss`: цвета ролей, шкалу заголовков (`fluid-text`), размер body.

## 3. Порядок вёрстки

1. Токены → глобальные стили → `utils.scss`.
2. Примитивы: `Icon` → `Button` → `Logo` → прочие.
3. `Header`, `Footer`, `Content`, `Section`.
4. Секции главной сверху вниз, затем остальные страницы.
5. JS-модули по мере появления интерактивных блоков (подключить в `main.js`).
6. Адаптив проверять **по ходу работы над каждой секцией**, а не в конце.

## 4. Проверка

Пройти `07-checklist.md`. Обязательно открыть страницы на ширинах **1920, 1440, 1280, 1024, 768, 480, 390, 360** и сверить с дизайном (скриншоты через браузер, если он доступен). Выполнить `npm run build`: сборка должна пройти без ошибок.
